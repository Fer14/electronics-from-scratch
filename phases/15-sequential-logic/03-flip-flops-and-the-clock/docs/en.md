# Flip-Flops and the Clock

> A flip-flop looks at its input for one instant per clock tick and ignores it the rest of the time. That instant is what makes large digital systems predictable.

**Type:** Build
**Prerequisites:** Phase 15 (Sequential Logic), Lesson 01 (Memory from Feedback) and Lesson 02 (Latches)

## Words You'll Meet

| Word | Plain meaning | Everyday picture |
|---|---|---|
| Clock | A signal that switches between 0 and 1 at a steady rate, used to pace a circuit | The beat of a metronome that a whole orchestra follows |
| Period (T) | The time of one full clock cycle | The time between two ticks |
| Frequency (f) | Cycles per second, `f = 1 / T`, in hertz (Hz) | Ticks per second |
| Duty cycle | The fraction of the period the clock is high | The fraction of each beat the baton is up |
| Edge | The instant a signal changes: rising (0 to 1) or falling (1 to 0) | The click of the metronome |
| Flip-flop | A memory element that changes only at a clock edge | A camera that takes exactly one photo per click |
| Edge-triggered | Responding to the edge, not to the level | Reacting to the moment a door opens, not to it being open |
| Master-slave | A flip-flop made of two latches that are open on opposite halves of the clock | An airlock: the inner and outer doors are never open together |
| Synchronous | Everything changes on the same clock edges | Soldiers marching in step |
| Timing diagram | A drawing of several signals against time, one under another | A musical score with one line per instrument |
| Toggle | Flip to the opposite value | Pressing a push-on/push-off pen |

## The Problem

Lesson 02 ended with a warning. A latch is transparent while enabled, so a loop that goes from a latch's output, through some logic, back into its input runs freely while the latch is open: it oscillates or races, and the stored result depends on exact gate delays. But loops are exactly what we need. A counter computes "next value = current value + 1" and stores it in the same place. A processor computes "next state from the current state" billions of times.

The solution that made modern digital design possible is to separate **computing** from **storing** in time. A shared signal, the **clock**, ticks steadily. Between ticks, the combinational logic computes the next values from the current ones, glitches and all (Phase 14, Lesson 06). At each tick, all memory elements take their new values at once and then close again, so the logic sees a stable new state and starts over. The memory element that does this is the **edge-triggered flip-flop**.

## The Physics

A clock is generated by an oscillator. The simplest is the ring oscillator of Lesson 01, but its frequency drifts with temperature and supply. Real systems use a **quartz crystal**: a thin slice of quartz that vibrates mechanically at a very precise frequency (quartz is piezoelectric, so the vibration produces a voltage and a voltage drives the vibration). A crystal and an inverter amplifier make an oscillator accurate to about 20 parts per million: a 16 MHz crystal is off by at most about 320 Hz. Inside chips, a **phase-locked loop** multiplies this reference up to GHz rates.

The clock is then distributed to every flip-flop through a tree of buffers, so that the edge arrives everywhere at almost the same time. Delivering one sharp edge to millions of flip-flops is a big physical job: the clock network can use a third of a processor's power (Phase 14, Lesson 05: every transition costs `C V^2`, and the clock switches every cycle). The small differences in arrival time, called **clock skew**, come back in Lesson 07.

## The Concept

### Describing a clock

```
        |<------ T ------>|
         _______           _______           _______
 clk ___|       |_________|       |_________|       |___
        ^       v         ^       v
     rising  falling   rising  falling
      edge    edge      edge    edge
```

The **period** `T` is the time from one rising edge to the next. The **frequency** is how many periods fit in one second. Say it as a sentence: "the frequency is one divided by the period".

```
f = 1 / T          T = 1 / f
```

Worked examples (check with a calculator):

```
f = 1 kHz    ->  T = 1 / 1000      = 1 ms       high for 500 us at 50 % duty
f = 16 MHz   ->  T = 1 / 16e6      = 62.5 ns    (a typical microcontroller crystal)
f = 3.2 GHz  ->  T = 1 / 3.2e9     = 312.5 ps   (a desktop processor)
```

The **duty cycle** is the fraction of the period spent high. Most clocks are near 50 %.

### What we want from a memory element

We want a box with a data input `d`, a clock input `clk` and an output `q` that obeys one rule: **at each rising edge of `clk`, `q` takes the value `d` had just before the edge, and holds it until the next rising edge.** In between edges, `d` may change as often as it likes; `q` does not care.

Say it with the next-state notation of Lesson 02: `Q+ = d`, where `Q+` now means "the value after the next rising edge". This box is the **D flip-flop**. Its schematic symbol has a small triangle on the clock input, which means "edge-triggered":

```
       +-----+
  d ---| D  Q|--- q
       |     |
 clk --|>    |
       +-----+
```

### Building it from two latches

Take two D latches (Lesson 02) in series. Call the first one the **master** and the second the **slave**. Give the master the inverted clock as its enable, and the slave the clock itself:

```
          +--------+         +--------+
   d ---->| D    Q |-- m --->| D    Q |----> q
          | master |         | slave  |
     +--->| en     |    +--->| en     |
     |    +--------+    |    +--------+
   [NOT]                |
     |                  |
 clk +------------------+
```

Follow one clock cycle:

- **clk = 0:** the master's enable is `clk' = 1`, so the master is transparent: `m` follows `d`. The slave's enable is 0, so the slave holds and `q` does not change.
- **clk rises to 1:** the master closes, freezing `m` at the value `d` had just before the edge. At the same moment the slave opens and copies `m` to `q`.
- **clk = 1:** the master holds (so `d` changes are ignored); the slave is transparent, but its input `m` is frozen, so `q` stays put.
- **clk falls to 0:** the slave closes (holding `q`), and the master opens again to watch `d`.

At no moment are both doors open, exactly like an airlock. A change at `d` can never run straight through to `q`. The only time `d` matters is the instant of the rising edge. The flip-flop is **edge-triggered** even though it is built from two **level-sensitive** latches.

### A timing diagram

This is what the simulator prints for twelve half-cycles of the clock (each character is half a period; `‾` is 1, `_` is 0):

```
  clk _‾_‾_‾_‾_‾_‾
  d   __‾‾‾___‾‾_‾
  m   __‾‾‾‾__‾‾__   master: follows d while clk = 0
  q   ___‾‾‾‾__‾‾_   slave:  changes only when clk rises
```

Read it column by column. In the 4th column, `clk` is high and `d` is 1; the master holds its 1. In the 5th column `clk` is low and `d` is still 1; nothing changes at `q`. In the 6th column `d` falls while `clk` is high: the master ignores it (it is closed), so `m` stays 1 and `q` stays 1. Only at the next rising edge, after `d` was 0 during the low half, does `q` fall. The values of `d` just before each rising edge are `[0, 1, 1, 0, 1, 0]`, and the values of `q` just after are exactly the same list, one cycle later. That one-cycle delay is the essence of a flip-flop: **q is d, delayed to the next edge**.

### The toggle, revisited

Connect `d` to `NOT q`. With a single transparent latch this was a ring oscillator: the simulator reports that the gates never settle. With a master-slave flip-flop:

- During `clk = 0`, the master copies `d = q'`, but `q` cannot change because the slave is closed. So the master settles at `q'`.
- At the rising edge, the slave copies the master: `q` becomes the old `q'`. Now `d = q'` changes too, but the master has just closed, so it does not see it until the next low phase.

Result: exactly one toggle per rising edge.

```
  clk _‾_‾_‾_‾_‾
  q   _‾‾__‾‾__‾
```

`q` completes one full cycle for every two clock cycles: its frequency is half the clock's. This **divide-by-two** is the first stage of every counter and frequency divider (Lesson 05).

### Synchronous design

With flip-flops, a digital system becomes a simple, repeating pattern:

```
         +---------------------------------------+
         |                                       |
         v                                       |
   +-----------+     +---------------------+     |
   | flip-flops|---->| combinational logic |-----+---> outputs
   |  (state)  |     |  next = f(state,in) |
   +-----------+     +---------------------+
         ^                     ^
        clk                 inputs
```

At each rising edge, every flip-flop takes its new value at once. Between edges, the logic computes the next values. As long as the logic finishes before the next edge (Lesson 07 makes this precise), the glitches inside it never reach any flip-flop. Designers can then reason about the circuit one clock cycle at a time, which is why almost every chip is designed this way. Our simulator offers exactly this model: `lc.dff(d, q)` adds a flip-flop, and `lc.step(inputs)` means "apply these inputs, let the logic settle, then one rising clock edge".

### Flip-flop flavours

The D flip-flop is by far the most common today, but you will meet others in datasheets:

- **JK flip-flop:** inputs J and K act like set and reset at the edge, and `J = K = 1` toggles instead of being forbidden: `Q+ = J·Q' + K'·Q`.
- **T flip-flop:** toggles at the edge when `T = 1`, holds when `T = 0`: `Q+ = T ⊕ Q`. A D flip-flop with an XOR in front of it.
- **Flip-flops with enable:** `Q+ = en·d + en'·Q`, a mux in front of a D flip-flop (Lesson 04).
- **Asynchronous set/reset:** extra pins (often active-low, `PRE'` and `CLR'`) that force `q` immediately, without waiting for a clock edge. Used for power-on reset.

## Build It

The script `code/main.py` builds the flip-flop from latches, drives it with a clock, and compares it with the simulator's built-in flip-flop.

### Step 1: A reusable D latch

The same five-gate NAND latch as Lesson 02, as a builder function:

```python
def add_d_latch(lc, en, d, q, tag):
    lc.not_(f"{tag}.nd", d)
    lc.nand(f"{tag}.sn", d, en)
    lc.nand(f"{tag}.rn", f"{tag}.nd", en)
    lc.nand(q, f"{tag}.sn", f"{tag}.qb")
    lc.nand(f"{tag}.qb", f"{tag}.rn", q)
```

### Step 2: Master and slave

```python
def master_slave(feedback=False):
    lc = LogicCircuit("master-slave D flip-flop" + (" with d = NOT q" if feedback else ""))
    lc.inputs("clk") if feedback else lc.inputs("clk", "d")
    lc.not_("nclk", "clk")
    if feedback:
        lc.not_("d", "q")
    add_d_latch(lc, "nclk", "d", "m", "master")
    add_d_latch(lc, "clk", "m", "q", "slave")
    lc.outputs("m", "q")
    return lc
```

With `feedback=True`, the flip-flop's own output drives its `d` through an inverter.

### Step 3: Drive a clock and draw the waveforms

We alternate `clk` between 0 and 1 and change `d` at chosen half-cycles, recording `m` and `q` after each half-cycle. A tiny helper turns a list of bits into a waveform string:

```python
def waveform(values):
    return "".join("‾" if v else "_" for v in values)
```

Before recording, the script gives the flip-flop one clock edge with `d = 0` so that it starts from a known state (like a reset).

### Step 4: The built-in flip-flop

```python
lc = LogicCircuit("built-in dff")
lc.inputs("d")
lc.dff("d", "q")
lc.outputs("q")
q_values = [lc.step({"d": value})["q"] for value in [0, 1, 1, 0, 1, 0]]
```

`step` represents one complete clock cycle ending in a rising edge, so the clock does not appear as a wire. The output matches the gate-level flip-flop edge for edge:

```
  d at each edge: [0, 1, 1, 0, 1, 0]
  q after edge:   [0, 1, 1, 0, 1, 0]
  matches the gate-level flip-flop: True
```

From the next lesson on we use `dff` and `step` directly: 11 gates per bit are fine for understanding, but a 64-bit register would be 704 gates of bookkeeping.

### Step 5: The toggle

```
  one transparent latch with clk = 1: the gates never settle: a feedback loop keeps oscillating
  master-slave flip-flop: clk _‾_‾_‾_‾_‾
                          q   _‾‾__‾‾__‾   one toggle per rising edge, half the clock frequency
```

## Use It

- **74HC74** holds two D flip-flops with asynchronous preset and clear; **74HC174** six with a common clear; **74HC574** eight with tri-state outputs.
- **Every register in a processor** (Phase 16) is a row of D flip-flops sharing one clock.
- **Frequency dividers.** A 32,768 Hz watch crystal through 15 toggle stages gives exactly 1 Hz, because 32,768 = 2^15. That is why watch crystals have that strange frequency.
- **Clock specifications.** Microcontroller datasheets give a maximum clock frequency (for example 16 or 48 MHz) and the crystal tolerance; processors list base and boost frequencies, which the PLL adjusts on the fly.
- **Standard cells.** A chip library's DFF cell is roughly 20-25 transistors, about five times a NAND2. Flip-flops are expensive, so designers count them (Phase 20).

## Common Mistakes

- **Confusing latch and flip-flop.** A latch is level-sensitive (transparent for a whole half-cycle); a flip-flop is edge-triggered (samples at one instant). The symbol triangle on the clock pin marks a flip-flop.
- **Expecting q to change at the same edge that d is read.** `q` shows the value of `d` from just before the edge, after a small delay. In a timing diagram, `q` always lags `d` by a cycle.
- **Changing d right at the edge.** The flip-flop needs `d` stable a little before (setup time) and a little after (hold time) the edge. Lesson 07 quantifies this.
- **Generating clocks with logic.** Feeding a gate's output (which may glitch) into a clock pin gives extra, unwanted edges. Use a clean clock and an enable instead (Lesson 04).
- **Forgetting the start-up state.** Flip-flops power up in a random state. Use a reset (asynchronous clear or a synchronous reset input) before relying on their contents.

## Key Terms

| Term | What people say | What it actually means |
|---|---|---|
| Clock | "clk" | A periodic square wave whose edges tell flip-flops when to sample |
| Period / frequency | "T and f" | `T = 1/f`: time per cycle and cycles per second |
| Rising edge | "Posedge" | The 0 to 1 transition; most flip-flops sample here |
| D flip-flop | "Flop", "DFF" | Edge-triggered memory: at each rising edge `q` takes the value of `d` |
| Master-slave | "Two latches back to back" | Latches enabled on opposite clock phases, so no path is ever transparent end to end |
| Edge-triggered | "Clocked" | Changes only at an edge, ignoring the input the rest of the time |
| Synchronous design | "Everything on one clock" | All state held in flip-flops sharing a clock; logic computes between edges |
| Timing diagram | "Waveforms" | Signals plotted against time, aligned so cause and effect can be read |
